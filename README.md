# Конвертер изображений · лабораторная работа № 8

Ветка `28` запускает конвертер в четырёх контейнерах. Nginx отдаёт сборку React и проксирует REST API и Socket.IO в Express. Данные сохраняются в именованных томах PostgreSQL и MongoDB.

| Хранилище | Данные |
| --- | --- |
| PostgreSQL, Sequelize | Аккаунты, хеши паролей, роли и задачи конвертации (`Users`, `Images`). |
| MongoDB, Mongoose | Личные пресеты конвертации (`conversion_presets`). |

В документе пресета `ownerId` соответствует идентификатору пользователя в PostgreSQL. Пресет содержит массив `outputs` с форматом, размерами и фильтром для каждого результата. В реляционной модели такие настройки можно было бы хранить в таблице пресетов и связанной таблице выходных форматов. Здесь отдельную настройку можно изменить позиционным оператором `$` в одном документе.

## Запуск

Понадобятся Docker Engine и Docker Compose v2 или новее.

```sh
cp -n .env.example .env
docker compose up --build
```

Перед запуском задайте в `.env` свои значения `JWT_SECRET` и `POSTGRES_PASSWORD`. Для запуска в фоне используйте `docker compose up --build --detach --wait`. При запуске Express дожидается готовности обеих баз через Compose и применяет миграции Sequelize перед открытием HTTP-порта.

| Назначение | Адрес или команда |
| --- | --- |
| Сайт | [http://localhost](http://localhost) |
| Express | [http://localhost:5000](http://localhost:5000) |
| Проверка процесса Express | `curl -f http://localhost:5000/health` |
| Контейнеры и их состояние | `docker compose ps` |
| Логи Express | `docker compose logs -f backend` |
| Остановить стек с сохранением данных | `docker compose down` |

Если порт 80 занят, задайте `FRONTEND_PORT=8080` в `.env` и откройте [http://localhost:8080](http://localhost:8080). Порт Express меняется через `BACKEND_PORT`. Базы доступны внутри сети Compose по именам `postgres` и `mongo`. Docker публикует порты сайта и Express только на loopback.

Сборка использует образы `node:24-alpine`, `nginx:alpine`, `postgres:16-alpine` и `mongo:8.0` из Docker Hub. Если реестр недоступен, настройте доступное зеркало в Docker Engine и повторите сборку.

Для разработки с локально запущенными базами используйте `npm ci`, `npm run db:migrate` и `npm start`. Клиент запускается отдельно через `npm --prefix client ci && npm --prefix client run dev`, с адресом API из `client/.env`.

## Проверка синхронизации в двух окнах

1. Откройте приложение в двух окнах с разными аккаунтами. В панели **Уведомления о задачах** проверьте статус соединения и число подключений.
2. Создайте в первом окне задачу и поменяйте её статус на **Выполнена**. Во втором окне без перезагрузки появится задача, обновится её статус и изменятся счётчики.
3. Во втором окне оставьте фильтр **Выполнена** и открытый черновик новой задачи. Удалите выполненную задачу из первого окна. Во втором окне запись исчезнет, фильтр и черновик сохранятся.
4. Временно отключите сеть во втором окне через инструменты разработчика и дождитесь статуса переподключения. Измените очередь из первого окна, затем верните сеть. После переподключения список во втором окне обновится. Выход из аккаунта уменьшит число подключений в первом окне.

Клиент подписывается через `queue:watch` и получает подтверждение с числом подключений. Сервер рассылает `queue:presence` при входе и выходе участников и `task:changed` после успешной операции в PostgreSQL. Получив `task:changed` или подтверждение подписки, клиент запрашивает актуальный список у `GET /api/images`. Это восстанавливает состояние очереди и после пропущенных событий. Лента хранит до 20 событий в памяти вкладки.

## Пресеты на сайте

После входа откройте **Управление пресетами** под именем файла. В разделе **Пресеты конвертации** можно создать пресет, добавить несколько выходных форматов с отдельными размерами и фильтрами, изменить или удалить пресет. Изменения сохраняются в MongoDB через API.

В форме задачи выберите пресет и выходной формат в поле **Применить пресет**. Форма подставит формат, размеры и фильтр. При сохранении задачи эти параметры записываются в PostgreSQL.

## API пресетов

Создайте аккаунт через `POST /api/auth/register` и получите токен через `POST /api/auth/login`. Оба запроса принимают JSON с `email` и `password`. Для всех запросов к пресетам передавайте заголовок `Authorization: Bearer <token>`. В URL используйте `_id` из ответа MongoDB.

| Метод и путь | Действие |
| --- | --- |
| `GET /api/presets` | Список пресетов текущего пользователя. |
| `GET /api/presets/:id` | Получить пресет. |
| `POST /api/presets` | Создать пресет с именем и массивом настроек. |
| `PUT /api/presets/:id` | Заменить имя и массив настроек пресета. |
| `PATCH /api/presets/:id/outputs/:format` | Изменить `width`, `height` или `filter` выбранного формата. |
| `DELETE /api/presets/:id` | Удалить пресет и вернуть удалённый документ. |

Пример тела для `POST` или `PUT`.

```json
{
  "name": "Для сайта",
  "outputs": [
    { "targetFormat": "webp", "width": 1200, "height": null, "filter": "none" },
    { "targetFormat": "avif", "width": 640, "height": null, "filter": "grayscale" }
  ]
}
```

Отправьте `{"width": 960}` через `PATCH /api/presets/:id/outputs/webp`, чтобы поменять ширину WebP. Значение `null` для размера означает исходный размер. Поддерживаются `png`, `jpeg`, `webp`, `avif`, каждый формат может встречаться в пресете один раз.

Чтобы посмотреть сохранённые документы в контейнере, выполните команду.

```sh
docker compose exec mongo mongosh image_converter_db --quiet --eval 'db.conversion_presets.find().toArray()'
```

## Проверка в Postman

Импортируйте `postman/lab6-presets.postman_collection.json`, задайте переменную `baseUrl` равной `http://localhost:5000` и запустите коллекцию через **Run collection**. Она регистрирует тестового пользователя, сохраняет JWT и ID пресета в переменные коллекции, проверяет CRUD и обновление элемента массива. После прогона пресет удаляется, тестовый аккаунт остаётся в PostgreSQL.

Чтобы увидеть вложенные настройки, выполните запросы по порядку до обновления ширины WebP и проверьте содержимое `conversion_presets` перед запросом на удаление.
